--- 3.4 Retrieval-Augmented Generation (RAG) Chatbots ---
What it is: A chatbot that answers questions using YOUR documents
instead of relying only on the model's general knowledge.

How RAG works (simple explanation):
1. Your documents are split into small chunks.
2. Each chunk is converted into a vector embedding and stored in a
   vector database.
3. When a user asks a question, the question is also embedded.
4. The system retrieves the most similar chunks.
5. Those chunks are passed to the LLM as context.
6. The LLM writes an answer grounded in that context, often with
   citations to the source.

Why RAG instead of fine-tuning:
- Answers stay up to date — just update the documents
- Cheaper and faster to implement
- Provides source citations for trust and verification
- Reduces hallucinations
- No retraining required

Typical RAG stack:
- Orchestration: LangChain, LlamaIndex, or custom code
- Vector databases: Pinecone, Weaviate, Qdrant, Chroma, pgvector,
  Milvus, FAISS
- Embeddings: OpenAI embeddings, Cohere, BGE, E5, Sentence-Transformers
- LLMs: GPT, Claude, Gemini, Llama, Mistral
- Backend: Python (FastAPI) or Node.js
- Frontend: React / Next.js chat interface

Advanced RAG features we implement:
- Hybrid search (keyword + vector)
- Reranking (Cohere Rerank, cross-encoders)
- Metadata filtering by department, date, or document type
- Multi-document and multi-format ingestion (PDF, DOCX, HTML, CSV, SQL)
- Conversation memory and follow-up question handling
- Streaming responses
- Source citations and confidence scores
- Access control so users only see permitted documents
- Analytics on unanswered questions to improve coverage

Timeline: a working prototype in 1–3 weeks; production system in 4–8 weeks.

12. FREQUENTLY ASKED QUESTIONS
====================================================================

Q: What is the difference between AI, Machine Learning, and
   Data Science?
A: Data Science is the broad discipline of extracting insights from
   data using statistics, programming, and domain knowledge.
   Machine Learning is a subset of AI where models learn patterns
   from data instead of being explicitly programmed. AI is the
   widest term, covering machine learning plus areas like NLP,
   computer vision, robotics, and generative AI.

Q: What is a RAG chatbot and why would I need one?
A: RAG (Retrieval-Augmented Generation) is a technique where the
   chatbot retrieves relevant passages from your own documents and
   gives them to a large language model as context before it
   answers. You need it when you want accurate, up-to-date answers
   grounded in your private content, with citations, and without
   the cost and delay of retraining a model.

Q: Can the chatbot answer questions about my own documents?
A: Yes. We ingest your PDFs, Word files, web pages, CSVs, and
   database records, then index them for retrieval. The assistant
   answers only from that knowledge base and cites its sources.

Q: Do you fine-tune models or use RAG?
A: We recommend RAG when knowledge changes frequently or when you
   need citations. We recommend fine-tuning when you need a
   specific tone, format, or a narrow task done very consistently.
   Often the best result is RAG plus light fine-tuning.

Q: How do you prevent the AI from making things up?
A: We ground responses in retrieved documents, instruct the model
   to say "I don't know" when context is missing, add confidence
   thresholds, cite sources, and run automated evaluation tests on
   a set of known question-answer pairs.

Q: Which LLM do you use — OpenAI, Claude, or open source?
A: We are model-agnostic. We choose based on accuracy, latency,
   cost, privacy requirements, and whether self-hosting is needed.
   We can also build a router that uses different models for
   different tasks.

Q: How much does a RAG chatbot cost?
A: A prototype typically starts in the low thousands; a production
   system with authentication, multiple data sources, analytics,
   and monitoring is a larger project. Final cost depends on the
   number of documents, integrations, and users. Contact us for a
   quote: [EMAIL].

Q: How long does it take to build an AI chatbot?
A: A working prototype takes 1–3 weeks. A production-ready system
   with security, evaluation, and integrations takes 4–8 weeks.

Q: What is MLOps?
A: MLOps is the practice of deploying, monitoring, and maintaining
   machine learning models in production — including versioning,
   automated retraining, drift detection, and CI/CD for models.

Q: What is model drift?
A: Model drift is when a model's accuracy degrades over time
   because real-world data has changed. We monitor for it and set
   up automatic retraining schedules.

Q: Can you work with our existing data and systems?
A: Yes. We integrate with existing databases, CRMs, ERPs, data
   warehouses, APIs, and cloud accounts. We can also start with
   whatever data you have and improve quality as we go.

Q: Do we need a lot of data to start?
A: Not necessarily. For many use cases, pre-trained models and
   APIs get you far with little or no training data. For custom
   models, more labeled data helps, but we can often start with a
   small dataset and improve iteratively.

Q: What is a data warehouse and do we need one?
A: A data warehouse is a central, structured store for analytical
   data from multiple sources. You need one when reporting is slow,
   data lives in many disconnected tools, or different teams
   report different numbers for the same metric.

Q: What is the difference between a data lake and a data warehouse?
A: A data lake stores raw data in many formats cheaply and is
   flexible but unstructured. A data warehouse stores cleaned,
   modeled, structured data optimized for fast querying and
   reporting. Many companies use both — this is called a lakehouse.

Q: What is ETL vs ELT?
A: ETL transforms data before loading it into the warehouse.
   ELT loads raw data first and transforms it inside the warehouse,
   which is more common today because warehouse compute is cheap
   and scalable.

Q: What tech stack do you use for web apps?
A: Commonly React or Next.js with TypeScript on the frontend;
   Node.js/NestJS or Python/FastAPI on the backend; PostgreSQL or
   MongoDB for data; deployed on AWS, GCP, Azure, or Vercel with
   Docker and CI/CD. We choose based on your needs, existing
   skills, and long-term maintenance.

Q: Can you build both the website and the AI features?
A: Yes. That is our core strength — we deliver the full product:

Q: Do you redesign or fix existing websites and apps?
A: Yes. We perform audits, fix performance and security issues,

   features to existing products.

Q: Do you provide ongoing support after launch?
A: Yes. We offer monthly support and maintenance plans covering

Q: Who owns the code and the models?
A: You do, unless the contract states otherwise. We hand over

13. GLOSSARY
====================================================================
AI (Artificial Intelligence): Software that performs tasks normally
requiring human intelligence.

Machine Learning (ML): Models that learn patterns from data.

Deep Learning: Machine learning using multi-layer neural networks.

LLM (Large Language Model): A large neural network trained on text
that can generate and understand language, e.g. GPT, Claude, Llama.

RAG (Retrieval-Augmented Generation): Retrieving relevant documents
and giving them to an LLM so it answers with grounded context.

Embedding: A numeric vector representation of text, image, or audio
that captures meaning, used for similarity search.

Vector Database: A database optimized for storing and searching
embeddings by similarity.

Chunking: Splitting documents into small passages before embedding —
a key RAG quality factor.

Fine-tuning: Further training a model on your own examples to
specialize its behavior.

Prompt Engineering: Designing instructions and context that make an
LLM produce better output.

Hallucination: When an AI generates confident but incorrect content.

Inference: Running a trained model to get a prediction or response.

Token: A unit of text (roughly part of a word) that LLMs process;
API pricing is usually per token.

MLOps: Practices for deploying and maintaining ML in production.

ETL / ELT: Extract, Transform, Load / Extract, Load, Transform —
data pipeline patterns.

Data Warehouse: Central structured store for analytics.

Data Lake: Central store for raw data in any format.

BI (Business Intelligence): Tools and processes for reporting and
visualizing data.

KPI: Key Performance Indicator — a metric that measures success.

API (Application Programming Interface): A defined way for software
systems to communicate.

REST / GraphQL: Two common styles of web API.

Frontend: The user-facing part of an application.

Backend: The server-side logic and data layer.

Full Stack: Covering both frontend and backend.

CI/CD: Continuous Integration / Continuous Deployment — automated
build, test, and release pipelines.

Docker / Kubernetes: Tools for packaging and orchestrating
applications across servers.

Multi-tenant: One application serving many separate customers with
isolated data.

SaaS: Software as a Service — subscription-based hosted software.

MVP: Minimum Viable Product — the smallest version that delivers
real value to validate an idea.
